   - Run 1 (default): every GL client dies with SIGILL.
   - Run 2 (`QT_QUICK_BACKEND=software` + `KWIN_COMPOSE=Q`): KWin 6.8's DRM platform has no QPainter compositor (`Configured compositor not supported by Platform` -> `Could not fulfill the requested compositing mode in KWIN_COMPOSE ... Exiting`, SIGSEGV loop). Dead end.
   - Run 3 (`softpipe`: `LIBGL_ALWAYS_SOFTWARE=1` + `GALLIUM_DRIVER=softpipe`): KWin cannot initialise EGL (`Not allowed to force software rendering when API explicitly selects a hardware device`, `Found no render device!`, `We are going to quit KWin now as it is broken`).
5. **Root cause of the SIGILL (decoded, section 9.3):** the cores of kwin_wayland, plasmashell, ksplashqml and plasma-keyboard all die at the same instruction word `0x04a14003` in llvmpipe's JIT code = **`index z3.s, #0, #1`, an SVE instruction** (decoded with `llvm-mc`). `/proc/cpuinfo` has NO `sve`/`sve2`/`bf16` in `Features` although `CONFIG_ARM64_SVE=y`: the firmware/hypervisor hides SVE from the kernel. INFERENCE for why: LLVM picks its CPU model from the `CPU part` lines (Cortex-A510 0xd46 x3, A710 0xd47 x2, A715 0xd4d x2, X3 0xd4e x1, all SVE2-capable on paper), not from `Features`. dmesg also shows `CPU features: SANITY CHECK: Unexpected variation in SYS_ID_AA64MMFR1_EL1 ... Unsupported CPU feature variation detected` on CPU3-7 (unexplained, probably unrelated).
6. Other findings: Mesa first tries the msm gallium driver on renderD128 and fails because there is no GPU (`MESA: error: get_param:235: get-param failed! -6`, `fd_pipe_new2:34: allocation failed`), then falls back to llvmpipe; `/usr/lib/tmpfiles.d` has no x11.conf (`/tmp/.X11-unix`, `/tmp/.ICE-unix` were missing in run 2); `/etc/xdg/plasma-workspace/env/*.sh` is a working hook for session-wide environment variables (verified through `systemctl --user show-environment`); session unit quirk `XDG_VTNR=tty1` (pam_systemd warns, harmless).
7. **Decision (mine, 2026-10-18): do the GPU first.** A working Adreno removes llvmpipe from the picture (KWin and Qt Quick would use msm/freedreno), which is the proper fix instead of fighting software GL.
